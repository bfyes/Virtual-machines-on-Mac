    判断题 ¶

    1.

    mov ax, 0 执行后，零标志 ZF 会变为 1。（）

    点击查看答案

    ✗（错误）。mov 不影响任何标志位。AX 变成 0 但 ZF 不变。要让 ZF=1 必须用 sub ax, ax 或 xor ax, ax。

    2.

    jl（有符号小于则跳）的跳转条件是 SF ≠ OF，与 ZF 的值无关。（）

    点击查看答案

    ✓（正确）。调试器演示：比较 1 和 2（SF=1,OF=0），手动把 ZF 改成 1，jl 箭头依然亮——只看 SF 和 OF 是否不等，无视 ZF。

    3.

    两个正数相加变成负数时 OF=1，两个负数相加变成正数时 OF=1。（）

    点击查看答案

    ✓（正确）。举例：7Fh(127)+1=80h(-128)→OF=1；80h(-128)+0FFh(-1)=7Fh(+127)→OF=1。OF 是 CPU 假设操作数为有符号数设置的，非符号数的溢出看 CF。

    4.

    repne scasb 和 loop 对 CX 的处理方式相同：CX=0 时都循环 10000h 次。（）

    点击查看答案

    ✗（错误）。需注意：repne 先判断 CX=0，为 0 则 0 次循环；loop 先 dec 再判断，CX=0 时循环 10000h 次。二者相反。

    5.

    cmp 与 sub 的区别在于 cmp 不保存运算结果但影响标志位。（）

    点击查看答案

    ✓（正确）。cmp ax, bx 等价 sub ax, bx 但不写回 AX。cmp 后跟 je 等于 sub 后跟 jz。

    6.

    短跳（short jump）用 delta 编码而非绝对地址，目的是代码被复制到其他位置后仍能正确跳转。（）

    点击查看答案

    ✓（正确）。EB 06 中 06 = 目标 − 下条指令 = delta。代码从 1000:2000 复制到 1000:8000 后仍跳到正确相对位置。近跳（E9）用 2 字节 delta。

    7.

    test ah, 1 和 and ah, 1 的唯一区别是前者不保存结果，其余行为完全相同。（）

    点击查看答案

    ✓（正确）。test 做按位与但丢弃结果，仅影响标志位；and 写回目的操作数。

    8.

    neg ax 等价于 not ax 后 inc ax。（）

    点击查看答案

    ✓（正确）。neg ax = (not ax) + 1，结果值相同。唯一差异在 CF：neg 对非零操作数置 CF=1（内部做 0−AX 产生借位），inc 不影响 CF。

    举例：设 AX=2，初始 CF=0。 - neg ax：AX=0FFFEh(−2)，CF=1（2≠0，0−2 有借位） - not ax; inc ax：AX=0FFFEh(−2)，CF=0（inc 不改 CF）

    二者 AX 结果相同，CF 不同。

    9.

    sub 指令执行后，可以直接跟 js 判断结果是否为负，不需要中间再写 cmp。（）

    点击查看答案

    ✓（正确）。sub 之后已影响标志位，马上可以判断。再写 cmp 是多余的。

    10.

    cbw 的典型用途是为 idiv 准备被除数，把 AL 符号扩展到 AX。（）

    点击查看答案

    ✓（正确）。cbw/ cwd/ cdq的“意图”就是为 idiv 服务。cwd 把 AX 扩到 DX:AX，正是为 16 位 idiv 做准备。

    11.

    除法溢出（如除数为 0）产生 int 0 中断，该中断插在 div 指令的下方。（）

    点击查看答案

    ✗（错误）。注意：int 0 插在 div 指令的上方（前面）。“必然是 div 的上方会插到 int 0，不是在下面的”。

    12.

    在 mov ax, [bp+2] 中，缺省的段寄存器是 DS。（）

    点击查看答案

    ✗（错误）。[] 中有 BP 时，缺省段寄存器是 SS（堆栈段）；无 BP 只有 BX/SI/DI 时才是 DS。

    填空题 ¶

    1.

    十进制数 -12 的 8 位二进制补码为 ______ B。

    点击查看答案

    1111 0100。12=00001100B，取反加一。

    2.

    逻辑地址 1234h:0058h 对应的物理地址为 ______ h。

    点击查看答案

    12398h。物理地址 = 段地址 ×10h + 偏移 = 12340h + 0058h。

    3.

    设 AL=00h，执行 sub AL, 01h 后，CF= ______。

    点击查看答案

    1。0−1 产生借位。

    4.

    从地址 1000h:2000h 开始顺序存放 12h, 34h, 56h, 78h 四个字节，则word ptr [1000h:2002h] = ______ h。

    点击查看答案

    7856h。小端序：2000→12h, 2001→34h, 2002→56h( 低 ), 2003→78h( 高 )。

    5.

    近调用 call 压栈 __ 个值（仅压入 _）；远调用 call far 压栈 个值（先 后 ）；int 压栈 个值（顺序为 → → ___）。

    点击查看答案

    1、IP；2、CS、IP；3、FLAGS、CS、IP。返回指令对应 ret、retf、iret。总结：“一个 push、两个 push、三个 push 的区别”。

    6.

    neg ax 与 not ax 的关系：neg ax = (not ax) ______。

    点击查看答案

    + 1。-ax = ~ax + 1 恒成立。

    7.

    在 push bp; mov bp, sp 建立的堆栈框架中（near call + Pascal 方式），[bp+0]=__，[bp+2]=_，[bp+4]=___。

    点击查看答案

    old BP、返回地址 (IP)、最后一个参数。参数用 BP+N 引用，局部变量用 BP−N 引用。

    8.

    jl 的跳转条件为 __（用标志位表达式），该指令 ____（会 / 不会）受 ZF 影响。

    点击查看答案

    SF ≠ OF、不会。调试器验证：即使 ZF=1，jl 仍只看 SF 和 OF。

    单选题 ¶

    1.

    设 AL=7Fh，执行 add AL, 1 后，SF 和 OF 的值分别是（）

    (A) SF=0, OF=0

    (B) SF=0, OF=1

    (C) SF=1, OF=0

    (D) SF=1, OF=1

    点击查看答案

    D（SF=1, OF=1）。7Fh+1=80h，最高位 =1→SF=1；127+1=−128，正 + 正→负→OF=1。

    2.

    设 AL=0FFh，执行 add AL, 1 后，CF 和 OF 的值分别是（）

    (A) CF=0, OF=0

    (B) CF=1, OF=1

    (C) CF=1, OF=0

    (D) CF=0, OF=1

    点击查看答案

    C（CF=1, OF=0）。0FFh+1=100h，8 位溢出→CF=1。但 −1+1=0，正负相加永不溢出→OF=0。此例说明 CF 是非符号数溢出，OF 是有符号数溢出。

    3.

    repne scasb 扫描 "Hello\0"（6 字节）结束后，要得到字符串长度 6，应对 CX 做（）

    (A) inc cx

    (B) dec cx

    (C) not cx

    (D) neg cx

    点击查看答案

    C（not cx）。初始 CX=0FFFFh，扫描 6 次后 CX=0FFF9h，not cx = 0006h = 6。这是巧妙替代减法。

    4.

    关于 sal 和 shl 的说法正确的是（）

    (A) sal是算术左移，shl 是逻辑左移，行为不同

    (B) sal和 shl 完全等价

    (C) sal保持符号位不变

    (D) sal不能用于无符号数

    点击查看答案

    B（完全等价）。讲义中明确：sal ≡ shl，左移时算术和逻辑行为一致。

    5.

    设 AL=0FEh（−2），执行 sar AL, 1 和 shr AL, 1 的结果分别是（）

    (A) 0FFh, 7Fh

    (B) 7Fh, 0FFh

    (C) 0FFh, 0FFh

    (D) 7Fh, 7Fh

    点击查看答案

    A（0FFh, 7Fh）。sar：高位用符号位 (1) 填充→11111111=0FFh=−1；shr：高位用 0 填充→01111111=7Fh=127。对应 C 语言 signed char 和 unsigned char 右移差异。

    6.

    关于 lodsb 和 stosb，以下说法错误的是（）

    (A) lodsb = AL←DS:[SI], SI±1（DF=0 时递增）

    (B) stosb = ES:[DI]←AL, DI±1（DF=0 时递增）

    (C) DF=1 时 SI/DI 递减

    (D) lodsb使用目标指针 ES:DI

    点击查看答案

    D。注意：lodsb 从源取数用 DS:SI；stosb 存到目标用 ES:DI。源和目标不能混。

    7.

    xlat 指令的功能是（）

    (A) AL = DS:[BX + SI]

    (B) AL = DS:[BX + AL]

    (C) AL = ES:[DI + AL]

    (D) AL = DS:[SI]

    点击查看答案

    B（AL = DS:[BX + AL]）。以 AL 为下标、DS:BX 为基址查表，结果放回 AL。

    8.

    近调用 call（near call）执行时，CPU 将什么压入堆栈？（）

    (A) 只压入 FLAGS

    (B) 只压入 IP（返回偏移地址）

    (C) 先压入 CS 再压入 IP

    (D) 先压入 FLAGS 再 CS 再 IP

    点击查看答案

    B（只压入 IP）。总结：近调用 = 1 个 push(IP) + jmp。对应 ret（pop IP）。

    9.

    远调用 call far 执行时，CPU 的压栈顺序是（）

    (A) 先压入 IP，再压入 CS

    (B) 先压入 CS，再压入 IP

    (C) 先压入 FLAGS，再压入 CS，最后 IP

    (D) 只压入 CS

    点击查看答案

    B（先 CS，再 IP）。远调用 = 2 个 push(CS,IP) + jmp。压栈顺序 CS 先、IP 后，返回时 retf 先 pop IP 再 pop CS。

    10.

    int 指令执行时，CPU 的压栈顺序是（）

    (A) FLAGS → CS → IP

    (B) IP → CS → FLAGS

    (C) CS → IP → FLAGS

    (D) FLAGS → IP → CS

    点击查看答案

    A（FLAGS → CS → IP）。总结：int = 3 个 push + jmp。顺序是 FLAGS 先、CS 次之、IP 最后。对应 iret（pop IP→CS→FLAGS）。

    11.

    关于call / call far / int三种调用，以下正确的是（）

    (A) 三者压栈内容完全一样

    (B) call压 1 个值，call far 压 2 个值，int 压 3 个值

    (C) int不压入 FLAGS

    (D) 三者都用 ret 返回

    点击查看答案

    B。总结：call = 1 push (IP)；call far = 2 push (CS,IP)；int = 3 push (FLAGS,CS,IP)。返回指令对应 ret、retf、iret。

    12.

    在堆栈框架 push bp; mov bp, sp 之后（near call + Pascal 方式），[bp+4] 指向（）

    (A) old BP

    (B) 返回地址（back / IP）

    (C) 最后一个参数

    (D) 第一个局部变量

    点击查看答案

    C（最后一个参数）。说“倒背如流”：[bp+0]=old BP, [bp+2]= 返回地址 , [bp+4] = 最后一个参数。用 BP+N 引用参数，BP−N 引用局部变量。

    13.

    关于 C 语言和 Pascal 语言调用约定的区别，正确的是（）

    (A) C：参数从左到右压栈，调用者清理

    (B) C：参数从右到左压栈，调用者清理

    (C) Pascal：参数从右到左压栈，被调用者用 ret n 清理

    (D) Pascal：参数从右到左压栈，调用者清理

    点击查看答案

    B。C：从右到左 + 调用者清理（add sp, n）；Pascal：从左到右 + 被调用者清理（ret n）。C 从右到左是为支持 printf 可变参数。

    14.

    DOS 中断 int 21h 中，AH=9 的功能是（）

    (A) 显示字符，入口 DL= 字符

    (B) 键盘输入，出口 AL= 字符

    (C) 显示以 $ 结尾的字符串，入口 DS:DX→字符串

    (D) 退出程序，入口 AL= 返回码

    点击查看答案

    C。AH=1 键盘输入、AH=2 显示字符（DL）、AH=9 显示 $ 结尾串（DS:DX）、AH=4Ch 退出。

    15.

    8086 的中断向量表位于内存何处？（）

    (A) 0:0 ~ 0:3FFh

    (B) 40:0 ~ 40:3FFh

    (C) F000:0 ~ F000:FFFFh

    (D) B800:0 ~ B800:FFFFh

    点击查看答案

    A（0:0 ~ 0:3FFh）。256 个中断向量，每个 4 字节（IP:CS），占 400h 字节。int 8h 向量在 8×4=20h 处。

    16.

    修改中断向量（修改 int 8h 中断向量）的正确流程是（）

    (A) 直接写入新地址即可

    (B) cli → 写入新向量 → sti

    (C) 保存旧向量 → cli → 写入新向量 → sti → 退出前恢复旧向量

    (D) 保存旧向量 → 写入新向量 → iret 返回

    点击查看答案

    C。int 8h 示例的完整流程：(1) 保存旧向量；(2)cli；(3) 写新向量到 0:8×4；(4)sti；(5) 退出前恢复旧向量。cli/ sti之间操作须原子化防止竞态。

    17.

    调试中跟踪到 call 指令，想进入被调用函数内部应用（）

    (A) F7（trace into）

    (B) F8（step over）

    (C) F9

    (D) F5

    点击查看答案

    A（F7）。F7=trace into（进入函数），F8=step over（跳过）。调试 repne scasb 等也必须用 F7 才能逐步观察，F8 一步执行完。

    18.

    关于硬件断点，正确的是（）

    (A) bpmb x在变量被读取时中断

    (B) bpmb r在变量被执行时中断

    (C) bpmb w在变量被写入时中断

    (D) 80386 不支持硬件断点

    点击查看答案

    C（bpmb w 在写入时中断）。注意：bpmb x= 执行断点、bpmb r= 读断点、bpmb w= 写断点。8086 不支持硬件断点，80386 支持。

    补充习题（选择性看）¶

    1.（单选）

    用 TD 调试 repne scasb 时，在 repne scasb 这行按 F8，会发生什么？（）

    (A) 进入 scasb 内部逐步执行

    (B) 一次性执行完整个 repne 循环，停在下一行

    (C) 执行一次扫描比较后停在下一行

    (D) 程序崩溃

    点击查看答案

    B。repne scasb 是一个指令，F8（step over）会把它当作一步执行完。要用 F7（trace into） 才能每次只执行一次扫描（DI++、CX--），逐步观察循环过程。

    2.（单选）

    在 TD 中，执行 call f 时按 F7，下一步会停在哪里？（）

    (A) call的下一行

    (B) 函数 f 的第一条指令

    (C) ret指令

    (D) 随机位置

    点击查看答案

    B。F7=trace into，会进入 f 内部。F8=step over，会把整个 call 当作一步停在下一行。

    3.（单选）

    在 SoftICE 中，想在 var 变量被写入时中断，应使用（）

    (A) bpm x var

    (B) bpm r var

    (C) bpm w var

    (D) bpx var

    点击查看答案

    C（bpm w）。bpm x= 执行断点（execute）、bpm r= 读断点（read）、bpm w= 写断点（write）。bpx 是普通执行断点（软件断点），不是硬件断点。

    4.（填空）

    SoftICE 中，T 命令（F7）的功能是 __，P 命令（F8）的功能是 _，X 命令（F9/Ctrl+D）的功能是 ___。

    点击查看答案

    跟踪进入（trace into）、步过（step over）、运行程序（execute/go）。

    命令 快捷键 含义
    T F7 trace into，遇 call 进入函数内部
    P F8 step over，call 当一步执行
    X F9 / Ctrl+D execute / go，运行程序直到断点
    BPX F2 设软件断点
    HERE F4 运行到光标处
    U — 反汇编
    D — dump 查看内存
    R reg — 修改寄存器值
    RS F5 观察用户屏幕
    SRC F3 切换源码 / 机器码显示
    CLS — 清除命令窗
    . — 代码窗显示 CS:IP 指向的指令
    命令 含义
    bpmb/w/d addr x 硬件执行断点（x=execute）
    bpmb/w/d addr r 硬件读断点（r=read）
    bpmb/w/d addr w 硬件写断点（w=write）
    bpmb/w/d addr rw 硬件读写断点
    bpx addr 软件断点
    bl 列出所有断点
    be * / num 激活断点（* = 全部，num = 编号）
    bd * / num 禁用断点
    bc * / num 清除断点

    5.（单选）

    在 TD 中调试 div bl 时，若 BL=0，执行后会发生什么？（）

    (A) 跳过该指令继续执行

    (B) 程序结束

    (C) 触发 int 00h，调试器可能弹出异常提示

    (D) AX 变成 0

    点击查看答案

    C。除数为 0 触发 int 00h（除法溢出中断），在调试器中会看到异常或中断发生。int 00h 插在 div 指令上方，不是在下方。

    6.（填空）

    在 SoftICE 中，要查看地址 0:8×4 处的内容（即 int 8h 的中断向量），应先执行 d ______，该地址低字是 __，高字是 ____。

    点击查看答案

    0:20（8×4=32=20h）、中断处理程序偏移地址 (IP)、中断处理程序段地址 (CS)。每个中断向量占 4 字节，小端格式排列。

    7.（单选）

    用 TD 调试时，push bp; mov bp, sp 之后查看 SS:SP 区域，[bp+2] 处存储的是（）

    (A) 调用者的 BP 值

    (B) 返回地址（call 的下一条指令偏移）

    (C) 第一个参数

    (D) 垃圾值

    点击查看答案

    B。[bp+0]=old BP、[bp+2]= 返回地址 (IP)、[bp+4]= 第一个压入的参数。只有亲手 dump 过堆栈才能记住这个顺序。

    8.（单选）

    PSP（程序段前缀）的长度是多少？PSP 位于程序内存映像的什么位置？（）

    (A) 100h 字节，位于 code segment 之后

    (B) 100h 字节，位于程序开头（code segment 之前）

    (C) 200h 字节，位于 data segment 之前

    (D) 0 字节，不存在

    点击查看答案

    B（100h 字节，程序开头）。PSP 长 256 字节，在 DOS 加载 .exe 时放在程序内存最前面。用 TD 的 dump 功能查看 DS 指向的位置就能看到 PSP。pclife.asm 中通过 ds:[985h] 访问游戏状态就是跨 PSP 操作。

    9.（填空）

    使用 int 1（单步中断）实现代码动态加密 / 解密的原理：先设置 __ = 1，CPU 在执行每条用户指令后自动触发 _，在中断处理程序中可以 下一条指令、同时 ___ 上一条指令，从而实现“执行时解密、执行后加密”的效果。

    点击查看答案

    TF（Trap Flag）、int 1、解密、加密。流程：

    1. 程序启动时所有代码处于加密状态（如每条指令与密钥 XOR）
    2. 设置 TF=1（通过 pushf; or word ptr [sp], 100h; popf）
    3. CPU 执行一条加密指令 → 自动触发 int 1
    4. int 1 处理程序：解密下一条指令（使 CPU 能正确执行）+ 加密上一条指令（恢复加密状态，防止静态分析）
    5. iret 返回 → 执行下一条（已解密的）指令 → 又触发 int 1 → 循环

    B。这是调试 int 1 加密程序的关键技巧：

    为什么不能用 P（F8）跟踪到 iret？

    SoftICE 自己也在使用 int 1 来实现单步调试。当用户程序设置了 TF=1 后，SoftICE 在自己的 int 1 处理逻辑中 无法区分这个 TF=1 是 SoftICE 自己搞出来的还是用户程序搞出来的。当它搞不清楚的时候，会假设 TF=1 是自己所为，然后在某个环节偷偷把 TF 清零。结果：你的程序退出单步模式，后续的 int 1 再也不会触发了。

    正确做法： 1. 在 int 1 处理程序入口设一个断点（软件断点 F2 或硬件断点 bpmb 均可） 2. 断点命中后，观察堆栈 d ss:sp 确认返回地址（IP）、下一条要解密的指令位置 3. 不要继续 P（F8），直接打 X 命令（go）让程序全速运行 4. 程序会执行一条用户指令 → 触发下一个 int 1 → 再次命中 int 1 handler 的断点

    这样每次 int 1 都会断住，你可以观察每一步的解密 / 加密过程，同时 TF 不会被 SoftICE 误清。

    总结：调试 int 1 加密程序的口诀——在 handler 里设断点，用 X 不用 P。

    33.（填空 · 调试技巧）

    在 SoftICE 中调试 int 1 加密程序时，断点命中后想查看 " 当前这个 int 1 是插在哪条用户指令后面的 "，应查看堆栈。命令为 d ______，堆栈顶部三个值（从栈顶往下）依次为 ______、______、______。

    点击查看答案

    ss:sp（或 d ss:sp）、IP（返回偏移地址）、CS（返回段地址）、FLAGS。压栈顺序为 FLAGS → CS → IP，所以栈顶是最后压入的 IP。通过 u CS:IP 即可反汇编查看是从哪条指令之后触发的中断。

    例如观察到 CS:IP = 0684:0055，则说明 int 1 插在 0684:0055 的上方（即上一条指令执行完毕后触发）。u 0684:55 看到的指令就是接下来将要被解密并执行的指令。

    34.（判断）

    用 SoftICE 调试 int 1 加密程序时，如果在 int 1 处理程序的 iret 指令处按 F8（P）单步过去，SoftICE 不会误清 TF，程序仍能正常进入下一次 int 1。（）

    点击查看答案

    ✗（错误）。这正是 SoftICE 的局限性：一旦你 P 过 iret，SoftICE 在内部处理中可能会误判 TF=1 的来源，将其清零。正确的做法是在 handler 入口设断点后打 X（go） 而不是逐步跟踪。老师的原话：" 千万不要跟踪到 iret 里面去，这是 SoftICE 的局限性。"

    35.（单选 ·int 9h 键盘）

    在 int 9h 键盘中断处理程序中，通过 in al, 60h 读取键盘端口。按下空格键时读到 39h，松开时读到 0B9h。以下关于这两个编码的说法正确的是（）

    (A) 39h 和 0B9h 是两个完全无关的编码

    (B) 不同按键的按下和松开编码差值固定

    (C) 0B9h 是 39h 取反得到的

    (D) 此时相差 80h，且不同按键的按下和松开编码差值不固定

    点击查看答案

    B。键盘的 make code（按下）和 break code（松开）规律：最高位区分按下 / 松开——bit7=0 为按下，bit7=1 为松开。39h（0011 1001）→ 0B9h（1011 1001），正好差 80h。抹掉最高位后两者都是 39h，代表同一个键。

    少数按键（如右 Ctrl）还有扩展码前缀 E0h/E1h，按下时依次产生 E0h 和 make code 两次 int 9h，松开时再产生 E0h 和 break code 两次。因此右 Ctrl 一共触发 4 次 int 9h。

    37.（单选 ·int 8h TSR）

    修改 int 8h 定时器中断实现驻留程序（TSR）时，让程序常驻内存并正常退出的 DOS 功能调用是（）

    (A) mov ah, 4Ch; int 21h

    (B) mov ah, 31h; int 21h

    (C) mov ah, 9; int 21h

    (D) mov ah, 0Ah; int 21h

    点击查看答案

    B（AH=31h）。int 21h AH=31h 是 DOS 的驻留退出（Terminate and Stay Resident），会保留指定大小的内存不释放，使得修改过的中断向量（如 int 8h）在程序退出后仍然生效。AH=4Ch 是普通退出（会释放所有内存，中断向量恢复原样）。TSR 程序的典型结尾：mov dx, (驻留代码长度+15)/16; mov ah, 31h; int 21h。

    38.（填空 ·int 21h 缓冲区）

    用 int 21h AH=0Ah 输入字符串，缓冲区定义为 buf db 20, ?, 20 dup(0)。用户输入 "Hello" 并回车后，buf[0] = __，buf[1] = _，buf[2] = ___。

    点击查看答案

    20（最大长度，不变）、5（实际输入字符数，不含回车）、'H'（输入内容的第一个字符）。AH=0Ah 缓冲区格式：[max_len][actual_len][data...]。buf[0] 是调用前预设的最大长度（20），调用后不变；buf[1] 被 DOS 填入实际读取的字符数（5）；buf[2] 起是输入内容。末尾的回车（0Dh）不被计入 actual_len。

    39.（判断 ·int 9h 键盘 · 有点偏）

    int 9h 中断处理程序末尾必须写 mov al, 20h; out 20h, al，这行代码的作用是告诉键盘 " 当前中断已处理完毕，可以发送下一次按键了 "。（）

    点击查看答案

    ✗（错误）。out 20h, al（AL=20h）发 EOI 的对象不是键盘，而是 8259A 中断控制器（PIC）。端口分工是：60h 跟键盘通信（in al, 60h 读扫描码），20h 是 PIC 的命令端口（发 EOI 告诉 PIC 可以放行后续中断）。如果搞混了，以为 20h 也是发给键盘的，就理解错了。不发 EOI 的后果：PIC 锁死，所有后续中断（包括键盘、定时器）全部进不来。
